# 日時境界の規則

DBにはUTC Unix timestampを保存し、入力・表示・日別集計には設定されたIANAタイムゾーンを使用する。

## 自動処理

日・月の開始、自動終了時刻は共通の規則で解決する。

- 夏時間開始などで存在しない時刻は、指定した現地日時の直後に存在する最初の時刻を採用する。
- 夏時間終了などで二度現れる時刻は、最初の出現を採用する。
- 日付全体が飛ぶ場合、その日の日付境界は次に存在する日付の開始と一致する。飛んだ日の活動時間は0秒となる。
- 自動終了期限は、開始・再開のUTC時刻より後である必要がある。重複時間帯の二度目に開始し、当日の最初の締切が過ぎていた場合は、翌日の締切を採用する。
- 解決不能な日時はエラーとして伝播する。自動終了ではトランザクションをロールバックし、記録を部分更新しない。

集計は実際のUTC経過秒数を日付ごとに分割する。そのため、夏時間の切り替え日は23時間または25時間になることがある。24時間への補正は行わない。

自動終了は開始・再開した現地日付の翌日以降に適用する。処理時点で締切がまだ到来していなければ、その時点では終了しない。通常は日付変更時と起動時の補完処理で適用する。

## 手入力

利用者が指定する開始・終了・修正日時には、上記の自動補正を適用しない。存在しない日時と二度現れる曖昧な日時は拒否し、一意に特定できる日時の入力を求める。

## 回帰試験

New Yorkの欠落した自動終了時刻・重複時刻・重複時間帯での開始、Havanaの深夜切り替えと23/25時間日、Apiaの日付全体の欠落を検証する。月次集計と帳票の日別合計がUTC経過秒数と一致すること、DBの自動終了が一度だけ適用されることを確認する。試験はダミーデータを使用し、Discordへ接続しない。
