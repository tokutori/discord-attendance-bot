# 常設の活動記録パネル

記録用 Bot が共用メッセージを所有し、`join｜活動開始` と `exit｜活動終了` の2ボタンを提供する。表示用 Bot が停止していても利用できる。時刻・備考の指定には `/join`・`/exit` を使う。

## 設置と復旧

1. 記録用 Bot を設定された Guild に起動する。新規 DB は初期 migration 1本で作成する。
2. Bot に対象チャンネルの View Channel・Send Messages・Embed Links を許可する。
3. サーバー管理権限（MANAGE_GUILD）を持つ管理者が、設置先のテキスト／アナウンスチャンネルで `/attendance panel` を実行する。

管理コマンドは初回のephemeral応答を先に送り、interactionに含まれる利用者・Botの権限で判定する。権限情報が欠ける場合も拒否し、権限照会のRESTを初回応答より先に行わない。

一般メンバーは共用パネルのボタンを押して自分の記録を操作する。管理者権限は設置・更新だけに必要。スレッドへの設置は対象外。

同じチャンネルで再実行すると登録済みメッセージを更新する。Discord が Unknown Message（10008）を返した場合だけ再作成する。権限不足・チャンネル削除・通信障害では再投稿せず、原因を解消して再実行する。

移動先のチャンネルで同じコマンドを実行するとパネルを置換する。新しいメッセージは無効なボタンで投稿し、DB 登録後に有効化する。登録が確定した時点から旧パネルでの新規記録を拒否する。旧メッセージの無効化に失敗して見た目が残っても、この判定は変わらない。不要な旧メッセージは管理者が削除する。

DB 登録に失敗した新メッセージは削除を試みる。削除失敗や投稿直後のプロセス終了で残った未登録メッセージは操作できず、管理者による削除が必要。登録後の有効化に失敗した場合は同じチャンネルで再実行する。再起動時の自動投稿は行わず、保存した Guild・Channel・Message・Application ID と常設イベントハンドラーを使う。単一の記録プロセスを前提とする。

## 記録と再受信

- 押した本人、Bot がイベントを受信した時刻、備考指定なしで、Slash Command と共通の記録処理を実行する。受信時刻は応答・DB 処理の前に1度だけ確定する。
- 活動中の join は開始時刻を変えない。手動終了後の exit は終了時刻を変えない。自動終了後の exit は共通処理に従って終了時刻を補正する。
- Guild、Application、メッセージ作者、member/user、Channel、登録 Message、component 種別、固定 custom ID を照合する。custom ID に対象ユーザーを埋め込まない。
- まず本人だけに見える遅延応答を送る。受付応答に失敗した場合（応答喪失で成否が不明な場合を含む）は新規記録を行わない。記録確定後の結果・通知も本人だけに返し、共用パネルへ個人情報を表示しない。
- 記録・監査履歴・interaction ID ごとの結果を同じ SQLite transaction で確定する。業務上の拒否も結果として保存する。同じ interaction は保存結果を利用し、後続の exit 後に古い join を再適用しない。Discordが受付済み（40060）を返す場合は保存結果の照会・再返信だけを試み、新規の記録変更は行わない。結果が未保存なら処理中または不明と案内する。
- commit 後の返信失敗では記録を維持する。再返信自体も通信障害・期限切れで失敗し得るため、必ず届くという保証はない。DB 結果が不明な場合は結果台帳を再照会し、更新を繰り返さない。結果を確定できなければ履歴確認を案内する。
- 管理コマンドの HTTP 待機中には DB transaction を保持しない。管理専用の直列化は記録コマンドをロックしない。

interaction の生成から15分を超えた操作、およびサーバー時刻より60秒を超えて未来の操作を拒否する。これは Bot の受付方針であり、パネルメッセージ自体の有効期限ではない。結果台帳は30日保持し、期限超過分は次の有効パネル操作で削除する。操作がない期間は削除が遅れる。台帳削除後も古い interaction は受付期限で拒否する。端末からの新たなクリックは別 interaction である。

`/attendance erase` は本人の結果台帳から所有者・送信元・操作内容・記録結果も削除する。再適用防止のため interaction ID と受信時刻だけの所有者との紐付けがない処理済み情報を残し、同じ30日・次回操作時の削除方針を適用する。バックアップや既に送信した Discord 応答には別途保持方針を適用する。

Discord の初回応答期限と interaction token の寿命は [Receiving and Responding](https://docs.discord.com/developers/interactions/receiving-and-responding) を参照する。ボタンの形式は [Component Reference](https://docs.discord.com/developers/components/reference) に従い、Components V2 は使用しない。

## 検証範囲

オフライン試験は状態遷移、競合、再接続後の重複排除、確定時刻、保存失敗時の rollback、完全消去、期限、入力境界、権限メタデータ、再設置の通信失敗を確認する。Discord への実送信・PC/モバイルの操作は代替しない。[受入確認](acceptance.md) で別途記録する。

試作中は後方互換を保証せず、初期 schema を統合する。既に古い初期 migration を適用したテスト DB は対象外であり、運用者が必要なデータを確認して新規 DB を用意する。アプリケーションが旧 DB を自動削除・変換することはない。
