Discord 活動時間記録 Bot 仕様書

対象: 鳥人間チームのメンバーごとの活動時間記録
実装言語: Rust
保存先: SQLite
作成日: 2026-08-06

1. 目的

Discord 上で各メンバーが活動開始・活動終了を記録し、個人ごとの活動履歴および月間活動時間を確認できる Bot を実装する。

本システムは給与計算や法令対応を目的とする厳密な勤怠管理システムではない。鳥人間チーム内の活動量を概算記録し、本人が後から修正できることを重視する。

2. 基本構成

  • Discord の Slash Command を操作入口とする。
  • Rust 製 Bot が command を処理する。
  • 活動記録は SQLite に保存する。
  • Google Spreadsheet 等への同期は行わない。
  • 各メンバーは自分の記録だけを閲覧・修正・削除できる。
Discord
  └─ /attendance ...
       └─ Rust Bot
            └─ SQLite

3. コマンド一覧

コマンド 引数 説明
/attendance start at, note 活動を開始する。
/attendance end at, note 現在の活動を終了する。
/attendance continue なし 直前の終了操作を取り消し、同じ記録を活動中へ戻す。
/attendance status なし 現在活動中か確認する。
/attendance history limit 最近の活動記録を表示する。
/attendance month target 指定月の本人の活動時間を Embed で表示する。
/attendance edit record, start, end, note 本人の既存記録を修正する。
/attendance delete record 本人の記録を削除する。

4. 状態モデル

利用者ごとの状態は、活動中と非活動中の2状態とする。

現在状態 操作 遷移後 処理
非活動中 start 活動中 新しい未終了記録を作成する。
活動中 end 非活動中 現在の未終了記録へ終了時刻を設定する。
非活動中 continue 活動中 直近の終了済み記録の終了時刻を削除する。
活動中 start 活動中 重複開始として no-op にする。
非活動中 end 非活動中 重複終了として no-op にする。
活動中 continue 活動中 すでに活動中であることを表示する。

5. 各コマンドの仕様

5.1 /attendance start

新しい活動記録を開始する。

引数

引数必須例意味
at任意13:30開始時刻。省略時は現在時刻。
note任意Pixhawkログ解析活動内容の備考。

正常時

活動を開始した。
開始時刻: 2026年8月6日 13:30
記録ID: #128

重複時

既に活動中なら、新しい記録を作成せず、既存の記録も変更しない。

すでに活動中である。

開始時刻: 2026年8月6日 13:30
経過時間: 3時間34分
備考: Pixhawkログ解析
記録ID: #128

at や note が指定されても、重複開始時には既存記録へ反映しない。修正は /attendance edit で行う。

5.2 /attendance end

現在活動中の記録を終了する。

引数

引数必須例意味
at任意18:00終了時刻。省略時は現在時刻。
note任意センサ試験完了終了時に記録へ設定する備考。

正常時

活動を終了した。
開始時刻: 2026年8月6日 13:30
終了時刻: 2026年8月6日 18:00
活動時間: 4時間30分
記録ID: #128

重複時

未終了記録が存在しない場合は、直近の終了済み記録を表示する。DB は変更しない。

現在、活動中の記録はない。

直近の活動:
2026年8月6日 13:30 ～ 18:00
活動時間: 4時間30分
記録ID: #128

5.3 /attendance continue

直前の /attendance end を取り消す。新しい記録は作らず、直近の終了済み記録の ended_at を NULL に戻す。

想定例

13:00 start
18:00 end
18:05 continue
21:00 end

最終的な記録は 13:00 ～ 21:00 の1件となる。

正常時

活動を継続状態に戻した。

開始時刻: 2026年8月6日 13:00
取り消した終了時刻: 2026年8月6日 18:00
現在の経過時間: 6時間05分
記録ID: #128

すでに活動中の場合

すでに活動中である。

開始時刻: 2026年8月6日 13:00
経過時間: 6時間05分
記録ID: #128

過去記録がない場合

継続できる直近の活動記録がない。

5.4 /attendance status

現在活動中か確認する。

活動中

活動中

開始時刻: 2026年8月6日 13:30
経過時間: 5時間28分
備考: Pixhawkログ解析
記録ID: #128

非活動中

現在、活動中の記録はない。

5.5 /attendance history

本人の最近の活動記録を Embed で一覧表示する。

引数

引数必須既定値範囲
limit任意51〜20

表示例

最近の活動記録
Bem130

🟢 #131  活動中
2026/08/06 18:30 ～ 現在
経過時間: 49分
センサ試験

#128  2026/08/06
13:30 ～ 18:00  4時間30分
Pixhawkログ解析

#124  2026/08/05
15:10 ～ 17:40  2時間30分
電装配線

表示中の合計: 7時間49分

備考が空の場合は備考行を省略する。活動中の記録は先頭に表示する。日を跨ぐ場合は開始日と終了日の両方を表示する。

5.6 /attendance month

本人の指定月の活動時間を Embed で表示する。ランキングは提供しない。

引数

引数必須例意味
target任意2026-08対象月。省略時は当月。

表示例

2026年8月の活動記録
Bem130

合計活動時間
42時間35分

活動回数
12回

1回あたり平均
3時間33分

日別
08/01  4時間20分
08/03  2時間15分
08/05  6時間10分
08/06  3時間30分

月を跨ぐ記録は、対象月に含まれる時間だけを集計する。

5.7 /attendance edit

本人の既存記録を修正する。

引数

引数必須例意味
record必須128修正対象の記録ID。
start任意2026-08-06 13:30修正後の開始日時。
end任意2026-08-06 18:00修正後の終了日時。
note任意電装作業修正後の備考。

start、end、note のうち少なくとも1つを指定する。本人の記録だけを修正可能とする。

5.8 /attendance delete

本人の活動記録を削除する。

引数

引数必須例意味
record必須128削除対象の記録ID。

削除前に確認ボタンを表示することが望ましい。DB 上では物理削除せず、deleted_at を設定する soft delete とする。

6. 時刻の扱い

  • DB には UTC の Unix timestamp を保存する。
  • 利用者向け表示は日本時間で行う。
  • at には HH:MM 形式を許可する。
  • edit には YYYY-MM-DD HH:MM 形式を使用する。
  • 終了時刻が開始時刻より前になる場合は、保存前に確認またはエラー表示を行う。

7. SQLite schema

CREATE TABLE attendance_sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    guild_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    display_name TEXT NOT NULL,

    started_at INTEGER NOT NULL,
    ended_at INTEGER,

    note TEXT,

    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    deleted_at INTEGER,

    CHECK (
        ended_at IS NULL
        OR ended_at >= started_at
    )
);

CREATE UNIQUE INDEX one_open_session_per_user
ON attendance_sessions (guild_id, user_id)
WHERE ended_at IS NULL
  AND deleted_at IS NULL;

CREATE INDEX attendance_sessions_user_history
ON attendance_sessions (
    guild_id,
    user_id,
    started_at DESC
)
WHERE deleted_at IS NULL;

8. データ操作規則

  • 未終了記録は、同一 guild・同一 user につき最大1件とする。
  • 重複 start と重複 end はエラー終了させず、no-op として現在状態を表示する。
  • continue は新しい記録を作らず、直近終了記録を再び未終了状態へ戻す。
  • 編集・削除時は、SQL 条件に guild_id と user_id を含める。
  • 削除済み記録は通常の検索・集計から除外する。
  • 表示名は参考情報として保存する。本人識別には Discord user ID を使用する。

9. 月間集計

対象月に重なる終了済み記録を取得し、月範囲との重複時間だけを加算する。

SELECT
    id,
    user_id,
    display_name,
    started_at,
    ended_at,
    note
FROM attendance_sessions
WHERE guild_id = ?
  AND user_id = ?
  AND deleted_at IS NULL
  AND ended_at IS NOT NULL
  AND started_at < ?
  AND ended_at > ?
ORDER BY started_at ASC;

各記録の月内時間は次の式で求める。

effective_start = max(started_at, month_start)
effective_end   = min(ended_at, month_end)
duration        = max(effective_end - effective_start, 0)

10. 応答の表示方針

  • 通常の操作結果は原則として ephemeral response とする。
  • history と month は Embed を使用する。
  • 表示内容は簡潔にし、記録ID、時刻、時間、備考を中心とする。
  • 備考がない場合は空の備考欄を表示しない。
  • エラー時も可能な限り現在状態または直近記録を表示する。

Discord interaction、domain logic、SQLite 操作、Embed 生成を分離する。月間集計や時間重複計算は Discord に依存しない純粋関数として実装する。
